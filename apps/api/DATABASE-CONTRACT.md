# Database Contract — Retainly API

This document is the authoritative handoff from the API team to the database team.
It describes every Prisma model the API runtime requires, including column names,
types, constraints, and index requirements.

The API consumes `PrismaClient` **only**. It does not run `prisma migrate` or modify
`prisma/schema.prisma` in CI beyond `prisma generate`. All DDL is owned by the
database team.

---

## Naming conventions

| Rule | Value |
|---|---|
| Table names | `snake_case`, plural |
| Column names | `snake_case` |
| Prisma field names | `camelCase` via `@map` |
| Primary keys | `UUID v4`, generated by the application or DB default |
| Tenant column | `organization_id` on every tenant-owned table |
| Soft-delete column | `deleted_at TIMESTAMPTZ NULL` where applicable |
| Money | `INT` minor units + ISO-4217 `currency VARCHAR(3)` |
| Timestamps | `TIMESTAMPTZ`, stored as UTC |

## AI-team interface

The API injects `RISK_SCORING_SERVICE` (symbol token) implementing:

```ts
interface IRiskScoringService {
  calculate(features: RiskFeatures): Promise<{ score: number; reasons: string[]; confidence: number }>;
}

interface RiskFeatures {
  studentId: string;
  organizationId: string;
  windowDays: number;          // always 30
  activityCount: number;
  daysSinceLastActivity: number | null;
  lessonCompletions: number;
  failedPayments: number;
  countsByType: Record<string, number>;
}
```

The default adapter (`RiskScoringAdapter`) POSTs JSON to `RISK_SCORING_URL` with
`Authorization: Bearer RISK_SCORING_TOKEN`, enforcing HTTPS and a 10-second timeout.
Replace the DI binding in `RiskModule` to provide an in-process implementation.

## Existing migrations note

`prisma/migrations/` is empty. The database team owns the initial migration.
Run `prisma generate` after the first migration to regenerate the typed client.
The API will fail at boot with a `ServiceUnavailableException` (P2021/P2022) for any
model that exists in `entities.ts` but is absent from the deployed schema.
